# Trace Analyzer

A React + TypeScript + Vite web application for analyzing QuestieTrace trace files (`.lua` format).

## Overview

The trace analyzer loads trace files generated by the QuestieTrace WoW addon and provides an interactive UI for:

- **Streams** - View function call streams over time (UnitRace, UnitClass, UnitLevel, GetZoneText, etc.)
- **Events** - Browse raw event log with timestamps
- **Position** - Visualize player position/movement on a 2D plot
- **Timeline** - Playback controls with variable speed and seeking
- **Extract** - Show the Questie DB corrections generated by [`tools/corrections-extractor`](../corrections-extractor/README.md) for copy/download: the four field modules (`npm run extract`) and, in the "Quest relations" tab, the quest relations module with its review report (`npm run relations -- pipeline`, see [its README](../corrections-extractor/src/relations/README.md))

## Prerequisites

- **Node.js** 18+
- **npm** (comes with Node.js)

## Installation

```bash
cd tools/trace-analyzer
npm ci
```

## Trace Files

The analyzer expects trace files (`.lua`) in the **QuestieTrace project root** at `Traces/`:

```
QuestieTrace/
├── Traces/
│   ├── your_trace_file.lua
│   └── another_trace.lua
├── tools/
│   └── trace-analyzer/     ← this project
```

The Vite dev server middleware automatically serves files from `../../Traces` relative to the trace-analyzer directory.

## Development

Start the development server:

```bash
npm run dev
```

This starts Vite on `http://localhost:5173` (default). The server includes API middleware at `/api/*` for loading trace data.

## How It Works

1. **Vite Dev Server** starts with `traceApiPlugin` middleware
2. Middleware scans `../../Traces/` for `.lua` files
3. Frontend fetches file list via `/api/files`
4. User selects a file → fetches sessions via `/api/file/:filename/sessions`
5. User selects a session → fetches full session via `/api/file/:filename/session/:name`
6. React components visualize the session data using emulated streams
7. The Extract tab fetches `/api/extract/:entity` (`npc`, `quest`, `item`, `object`), `/api/extract/relations` and `/api/extract/relations/review`, which serve the files from `../corrections-extractor/output/`

## Trace File Format

Trace files are Lua tables returned by QuestieTrace's export functionality. See `specs/TRACE_FILE_SPEC.md` in the QuestieTrace repo for the full schema.

Key structures:
- **Session**: Contains `events[]`, `functions{}`, `duration`, `startedAt`
- **Event**: `{ t: number, e: string, data: any[] }`
- **Function Call**: `{ name: string, args: any[], returns: any[], t: number }`

## Troubleshooting

**No trace files found**
- Ensure `.lua` files exist in `QuestieTrace/Traces/`
- Click "Reload" in the UI or call `GET /api/reload`

**Failed to load trace file**
- Check browser console / server logs for parse errors
- Verify the `.lua` file is valid QuestieTrace export format

**Extract tab shows "No generated corrections found"**
- Run `npm run extract` in `tools/corrections-extractor`, then click "Load all"

**Quest relations tab shows "No generated quest relations found"**
- Run `npm run relations -- pipeline` in `tools/corrections-extractor` (or `-- combine` if the candidates are current), then click "Reload"

**TypeScript errors**
- Run `npm run typecheck` to see full diagnostics
