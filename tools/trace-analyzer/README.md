# Trace Analyzer

A React + TypeScript + Vite web application for analyzing QuestieTrace submissions from the OVH archive bucket (or a local [trace-data](https://github.com/Questie/trace-data) checkout).

## Overview

The trace analyzer loads exports of the QuestieTrace WoW addon and provides an interactive UI for:

- **Streams** - View function call streams over time (UnitRace, UnitClass, UnitLevel, GetZoneText, etc.)
- **Events** - Browse raw event log with timestamps
- **Position** - Visualize player position/movement on a 2D plot
- **Timeline** - Playback controls with variable speed and seeking
- **Extract** - Show the Questie DB corrections generated by [`tools/corrections-extractor`](../corrections-extractor/README.md) for copy/download

## Prerequisites

- **Node.js** 18+
- **npm** (comes with Node.js)

## Installation

```bash
cd tools/trace-analyzer
npm ci
```

## Trace Data

Like the [corrections-extractor](../corrections-extractor/README.md), the analyzer reads the archive bucket through [rclone](https://rclone.org), which must be installed (the team's remote `ovhcloud-de:trace-intake-ovh`, or `TRACE_REMOTE`). It lists the submissions at start and downloads a submission when you open it; opened submissions stay in memory until you click "Reload".

Set `TRACE_DATA_DIR` to read a local `trace-data` checkout instead (`<dir>/submissions/<yyyy-mm>/<stamp>_<id>.json`).

Submissions are decoded natively by the dev server middleware (with the decoder of [`tools/corrections-extractor`](../corrections-extractor/README.md)) when they are opened. A submission holding several exports lists the sessions of all of them.

## Development

Start the development server:

```bash
npm run dev
```

This starts Vite on `http://localhost:5173` (default). The server includes API middleware at `/api/*` for loading trace data.

## How It Works

1. **Vite Dev Server** starts with `traceApiPlugin` middleware
2. Middleware lists the submissions in the bucket (or the `TRACE_DATA_DIR` checkout) and downloads one when it is opened
3. Frontend fetches file list via `/api/files`
4. User selects a file → fetches sessions via `/api/file/:filename/sessions`
5. User selects a session → fetches full session via `/api/file/:filename/session/:name`
6. React components visualize the session data using emulated streams
7. The Extract tab fetches `/api/extract/:entity`, which serves the files from `../corrections-extractor/output/`

## Trace File Format

Each submission's `export_string` holds the CBOR-encoded, compressed tables of QuestieTrace's export functionality. See `specs/TRACE_FILE_SPEC.md` in the QuestieTrace repo for the full schema.

Key structures:
- **Session**: Contains `events[]`, `functions{}`, `duration`, `startedAt`
- **Event**: `{ t: number, e: string, data: any[] }`
- **Function Call**: `{ name: string, args: any[], returns: any[], t: number }`

## Troubleshooting

**No submissions found**
- Check the terminal for an rclone error: is the remote `ovhcloud-de` configured (`rclone lsd ovhcloud-de:`)? Set `TRACE_REMOTE` for another remote, or `TRACE_DATA_DIR` for a local checkout
- Click "Reload" in the UI or call `GET /api/reload`

**Failed to load submission**
- Check browser console / server logs for the decoding error

**Extract tab shows "No generated corrections found"**
- Run `npm run extract` in `tools/corrections-extractor`, then click "Load all"

**TypeScript errors**
- Run `npm run typecheck` to see full diagnostics
